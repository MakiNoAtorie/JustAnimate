# Retro: `/implement-spec #139` (v0.1 Foundation), 2026-10-13

One cloud session (4 cores, 15 GB) orchestrating implementer and merger
subagents in worktrees. Stopped early for budget.

**Outcome:** 17 of 37 agent tickets merged into `integration/v0.1`
(`9055b33`, 75 test cases green), draft PR #146. CI green on Linux, macOS and
Windows at `f45370e`. Three tickets (#23, #32, #35) were nearly done but lost
as uncommitted worktree changes; three (#17, #18, #19) were stopped early.
`/code-review` never ran.

Findings below, most severe first. Each names the category, what happened,
and the proposed change.

---

## 1. Uncommitted work is lost when a run stops (workflow)

**What happened:** implementers commit once, at the end. When the run wrapped
up, #35 (coded, tests green), #23 (packaging, verified on Linux) and #32
(half done) existed only as uncommitted changes in local worktrees, and the
container is ephemeral. `CLAUDE.md` allows pushing only the integration
branch, so there was nowhere to put them.

**Change:**
- In the implementer brief: commit as soon as the ticket's test goes green
  (`git commit --fixup`/amend later is fine), so the one-commit rule is met by
  squashing at the end, not by holding everything uncommitted.
- In `CLAUDE.md`: allow pushing `wip/<ticket>-<slug>` branches on wrap-up, and
  delete them when the ticket merges.
- In `implement-spec`: add a **wrap-up** step: tell running implementers to
  commit and report, push `wip/*`, and list them in the PR body.

## 2. CPU oversubscription broke builds, tests and the benchmark (automated check)

**What happened:** up to 8 agents each ran Ninja at its default parallelism on
4 cores. Load average hit 47. Effects: builds slowed several-fold, a merger's
test run died with exit 144, and #31 recorded its benchmark baseline under that
load, so `docs/benchmarks.md` holds numbers that must be re-recorded. The fix
came late, as a prose `-j2` rule sent to each agent.

**Change:** make it deterministic instead of prose:
- `.claude/hooks/session-start.sh`: export `CMAKE_BUILD_PARALLEL_LEVEL=2` (and
  `CTEST_PARALLEL_LEVEL=2`) so every `cmake --build` is throttled without being
  told.
- `implement-spec`: cap concurrent implementers at about `nproc` (4 here), not
  "as many as the frontier allows".
- Benchmarks: never record a baseline inside a parallel run. The benchmark
  target should refuse, or warn loudly, when load average exceeds `nproc`.

## 3. Pattern kills and self-matching wait loops (tool economy)

**What happened:**
- One agent ran `pkill -f "cmake --build build"`. That pattern matches every
  worktree's build, and it likely caused the merger's exit-144 run.
- The #23 agent left two `while pgrep -f pkg/linux.sh; do sleep 5; done`
  loops. `pgrep -f` matched the loop's own command line, so they never exited
  and outlived the agent.

**Change:**
- Add a PreToolUse hook on Bash that rejects `pkill -f`, `killall`, and
  `while pgrep -f` with a message pointing to the alternatives: kill by PID,
  and use the Bash tool's `run_in_background` (which notifies on exit)
  instead of sleep loops.
- The "stop only processes you started" line in `docs/CONVENTIONS.md` stays
  as the explanation, but the hook is the guardrail.

## 4. A source file hidden by `.gitignore` broke Windows CI (automated check)

**What happened:** `app/app.cmake` lists `app/data/version.rc`, but a broad
`*.rc` rule in `.gitignore` meant the file was never committed. Linux builds
don't use it, so every local build passed, and Windows CI failed on about six
pushes before a fix landed.

**Change:**
- Narrow `.gitignore` to the generated files it meant (build-dir `.rc`
  outputs) instead of all `*.rc`.
- Add a cheap CI step on Linux that fails if any path named in a `*.cmake`
  file is missing from `git ls-files`. It catches this class on every OS
  without a Windows runner.

## 5. Mergers refused branches added after launch (workflow)

**What happened:** extending a running merger's queue with SendMessage got
refused by the permission classifier ("Modify Shared Resources"): the
branches weren't in the merger's original prompt. Five merges stalled until a
new merger was started with all branches named up front.

**Change:** in `implement-spec`: a merger's prompt names every branch it will
merge, and you start a new merger for later branches instead of extending a
running one. Fast-forward-only merges can be done by the orchestrator
directly.

## 6. The integration branch started from a stale local `master` (navigation)

**What happened:** local `master` was one commit behind `origin/master`, and
`git checkout -b integration/v0.1 master` used it. It was caught and
fast-forwarded, but only after the first push.

**Change:** in `CLAUDE.md` / `implement-spec`, write the exact command:
`git fetch origin master && git checkout -b integration/<m> origin/master`.

## 7. PR notifications from a dead workflow cost about 25 wake-ups (tool economy)

**What happened:** the draft PR was opened, and subscribed to, while the old
Pencil2D workflows still ran on early commits. Every one of their failures,
on superseded heads, woke the session; each was read and dismissed.

**Change:**
- Subscribe to PR activity only once the branch's own CI workflow is the one
  running, or only at the code-review stage when CI results matter.
- The new `ci.yml` already cancels superseded runs; old workflows can't be
  cancelled retroactively, so the timing of the subscription is the lever.

## 8. Subagents can't run the `tdd` skill as written (navigation)

**What happened:** implementers reported the `tdd` skill unavailable as a tool
and read `.claude/skills/tdd/SKILL.md` directly. The skill also asks to
confirm test seams with the user, which a background subagent can't do; each
implementer noted this as a deviation.

**Change:** in `implement-spec` step 4, tell implementers to read
`.claude/skills/tdd/SKILL.md` and state that the orchestrator pre-approves
seams at any public interface. (The session's brief did this from mid-run on.)

## 9. One MCP call returned 465 KB (tool economy)

**What happened:** `issue_read get_sub_issues` on the spec returned all 38
ticket bodies plus metadata (465 KB) in one call, which had to be parsed from
a saved file.

**Change:** `docs/agents/issue-tracker.md` already documents
`gh api ... --jq '{number,title,labels}'`; add one line to `implement-spec`
saying to use that REST form for the task graph and to save ticket bodies to
the scratchpad, never the raw MCP sub-issue dump.

## 10. Test registration is duplicated across two build systems (automated check)

**What happened:** every new test file had to be added to both
`tests/tests.cmake` and `tests/tests.pro`. Several merges conflicted there,
and one implementer (#12) skipped `tests.pro`.

**Change:** ticket #24 (remove qmake) removes the duplication. Until then, a CI
step that diffs the `tests/src/*.cpp` glob against `tests/tests.cmake` would
catch an unregistered test file.

## 11. No coding-standards file for the reviewer (coding standards)

**What happened:** the repo has no `CODING_STANDARDS.md`. Rules that are
judgement calls (test at a public interface, tests restore `QSettings`, use
the new undo system) were spread across ticket text and implementer notes.
`docs/CONVENTIONS.md` (added mid-run) now holds them, but `/code-review` only
finds standards by searching.

**Change:**
- Point the review skill at `docs/CONVENTIONS.md` explicitly (its standards
  search lists `CODING_STANDARDS.md`/`CONTRIBUTING.md`).
- Turn the mechanical rules into checks: "every new test file registered"
  (finding 10), "no missing source paths" (finding 4).
- Leave only judgement calls in prose. Candidate: tests that change
  `QSettings` restore it (the #1 test doesn't; flag in review).

## 12. Orchestrator mistakes worth a note (tool economy)

- An unquoted heredoc containing backticks ran `git` commands while writing
  a brief. Write files with the Write tool, or quote the heredoc (`<<'EOF'`).
- `git reset --hard` / force-push to fix the stale branch was refused; the
  fast-forward fix was the right move anyway. Prefer additive git operations
  on pushed branches.
